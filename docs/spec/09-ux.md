# 09 — UX and visual design

## 1. Principles (UX-1)

- **Chat-first management, screens for looking.** Admins can do everything by talking to the agent. Screens show state clearly and offer direct manipulation for common edits.
- **Coarse first, detail on demand** (§2).
- **Every number is traceable.** Tapping a macro shows target, actual and deviation, and where the target came from (daily × share, or an override).
- **Food first.** Dishes lead with name, cuisine flag, colour and a generated illustration. Numbers are secondary until asked for.
- Phone (390 px) and desktop are both first-class.

## 2. Progressive granularity (UX-2)

Every settings area has three levels. The UI shows the coarse level and an **"Add detail"** affordance that reveals the next level for that area only. Detail is remembered per area and per member, so one member can have expert settings while another stays simple.

| Area | Coarse (default) | Detailed | Expert |
|---|---|---|---|
| Targets | daily kcal + P/C/F | + training-day targets, sat-fat cap, soluble-fibre goal | + fibre, sodium; per-meal tolerance edit; strict/flexible |
| Meal split | automatic from slot weights | per-slot % per day kind | explicit per-slot macro targets |
| Slots | on/off for defaults | times, packed/reheat flags, custom slots | per-member weekday attendance grid, day overrides |
| Taste | liked/disliked cuisines (household) | per member cuisines + taste swipe | per ingredient/method/dish scores, locks, frequency rules |
| Planning | one "Balance" preset (Macros ▸ Appeal ▸ Economy) | weight sliders + fairness | weekday presets, adjuster list, max variants, window days, AI mode |

Reducing detail never silently deletes data. It asks "Keep your detailed settings hidden but active, or reset to automatic?"

## 3. Navigation (UX-3)

- **Mobile.** A bottom bar with Today · Plan · Recipes · Reviews · More, plus a floating chat button for admins (a chef-hat icon with a notification dot).
- **Desktop.** A left rail with the same items plus Family, Insights, Kitchen and Settings. The chat is a resizable right panel.
- Role-based: kitchen users land on **Kitchen**. Members see Today, Plan, Recipes, Reviews and My tastes.

## 5. Visual design system (UX-5)

**Mood.** A warm, well-lit family kitchen: recipe cards, enamel pots, spice jars, market produce. It should feel colourful and appetising, not clinical or like a fitness app.

**Colour tokens** (CSS variables, light and dark themes, both WCAG AA for text):

| Token | Light | Use |
|---|---|---|
| `--paper` | #FFF8EE | app background (recipe-card cream) |
| `--card` | #FFFFFF | surfaces |
| `--ink` | #2B2118 | text (espresso) |
| `--tomato` | #E4572E | primary actions |
| `--saffron` | #F3A712 | highlights, carbs |
| `--basil` | #3F8F3A | success, in-tolerance, vegetables |
| `--aubergine` | #5B2A86 | agent / AI accents |
| `--sea` | #1F8A8A | protein |
| `--olive` | #8A8A3A | fat |
| `--pomegranate` | #B3263E | errors, infeasible |
| `--flour` | #F1E7D6 | subtle fills, dividers |

The dark theme ("kitchen at night") uses `--paper` #1C1714, `--card` #26201B and `--ink` #F6EEE3, with the accents lightened 10–15 %. Macro colours are consistent everywhere: **P = sea, C = saffron, F = olive, kcal = tomato**.

**Typography.**
- Display: *Fraunces* (a soft, recipe-book serif) for headings and dish names.
- UI and body: *Nunito* (rounded, friendly).
- Numbers: *JetBrains Mono* tabular figures in macro tables.
- Self-hosted via `@fontsource` packages. No runtime Google Fonts dependency.

**Motifs and components.**
- Recipe-card surfaces: 16 px radius, a soft shadow, and a faint ruled-paper texture on recipe pages.
- Cuisine "stickers": rounded badges with a flag emoji and a slight rotation.
- Macro **rings** (a stacked P/C/F arc around the member avatar) and macro **bars** with a shaded tolerance band.
- A gingham (checkered tablecloth) pattern used sparingly: empty states and onboarding header.
- Food emoji as the rating scale (🤢 😕 😐 😋 🤩), mapped to 1–5.
- Dish illustrations: v1 uses a generated gradient + emoji composition per dish (deterministic from the dish id, cuisine and main ingredient). Real photos can be uploaded by the admin. AI image generation is out of scope.
- Lucide icons.

**Motion.** Framer Motion (`motion` package). Cards rise on load, the macro rings animate to their value, proposal Accept plays a short "stamp" animation, and plan generation shows a pot-stirring progress animation. `prefers-reduced-motion` is respected everywhere.

**Accessibility (UX-6).** Everything is keyboard-reachable, there are visible focus rings, colour is never the only carrier of status (fit badges also carry an icon and text), touch targets are ≥ 44 px, and screen-reader labels are given for rings and bars.

## 6. Empty, loading and error states (UX-7)

Every screen has a designed empty state that includes the next action ("No plan for tomorrow yet — Plan it" / "Ask the assistant"). Skeletons are used for loading. Errors show plain-language messages with a retry, and planner infeasibility states which member and macro could not be met, and by how much.
