# leaf-1.4.1 ADR-3: API contract, route definition, OpenAPI and the gate harness

Status: accepted at CP1 (R-40); as built at CP2
Requirement: ARC-4, ARC-5, ARC-6, ARC-10; G1, G3

## Decision

- **Contract** (`packages/api-contract/src/contract/*`): one `endpoint({ method, path, auth, roles, params?, query?, body?, response, errors })` entry per endpoint, Zod 4.6.5 schemas. `auth` is `public | session | household | operator | optional` (`optional`: invite acceptance, with or without a session); `roles` lists the household roles allowed (ARC-6 matrix). `ENDPOINTS` is the complete list.
- **Client** (`packages/api-contract/src/client/*`): `createApiClient({ baseUrl, fetch, headers })` typed from `ENDPOINTS`; parses responses with the same schemas; RFC 7807 errors as `ApiProblem`.
- **OpenAPI** (`packages/api-contract/src/openapi/*`): `buildOpenApiDocument()` assembles OpenAPI **3.1.1** from `ENDPOINTS` with Zod's built-in `z.toJSONSchema(schema, { target: "draft-2020-12", io })` (`io: "input"` for requests, `"output"` for responses; verified in the installed zod 4.6.5). Served at `GET /api/v1/openapi.json`. Validated in G3 with `@readme/openapi-parser` **9.0.0** (dev dependency requested), which checks against the official OAS 3.1 schema.
- **Routes** (`apps/web/app/api/v1/**/route.ts`): each exports `GET`/`POST`/… built by `route(ENDPOINT, handler)` from `apps/web/lib/server/route.ts`. `route` runs, in order: request id and log line, auth by the endpoint's `auth` kind (`requireHousehold` with the contract's `roles`, `requireSession`, `requireOperator`), params/query/body parsing (400 problem+json with issues), the handler (which calls services only, ARC-4), response serialisation through the contract schema (a response that fails its own schema is a 500 in tests), and maps typed service errors to problem+json (`application/problem+json`): `ZodError` and op validation → 400, `CrossHouseholdError`/`RowNotFoundError` and other not-found errors → 404, `ProtectedOperationError` and permission errors → 403, `LastAdminError`, undo conflicts, proposal state and a started job (`55006`) → 409, `ChangeOpError` and domain refusals → 422, the AI dish limit → 429. A response that fails its own schema is a 500 `response_invalid`, in production too.
- **Test harness** (`apps/web/test/api/support/*`): one database per test file (`CREATE DATABASE api_<uuid>`, migrated with the 1.1.2 migrator); route handlers are imported directly and called with standard `Request` objects (no `next dev`/`next build`, so gates share no `.next` directory). G2 wraps the same handlers in a `node:http` server on an ephemeral port (port 0).
- **G1 completeness**: the test walks `apps/web/app/api/v1/**/route.ts`, collects every exported method, and requires the set to equal `ENDPOINTS` (method + path) and every endpoint to appear in the contract table and in the authorisation matrix. Every endpoint also needs a valid-call case (`support/cases.ts`); the test fails for an endpoint without one. Per endpoint, `support/matrix.ts` runs: anonymous, blocked login, operator without household, each refused role, another household's admin naming this household (`X-Household-Id`) and, for id paths, with this household's ids (404), the contract's invalid inputs (400), the valid call of every allowed role (response parsed with the contract), and for list reads a leak check of another household's response. Negative controls reuse the same functions: an extra and a missing route file are reported; a route that skips the household and role check fails the matrix; a schema-violating response fails the contract check.
